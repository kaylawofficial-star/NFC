## 1. 整体设计

### 1.1 目标与规模假设

以 1–3 家单体口腔机构、每院先少量医生贴验证真实使用；这是规划假设，不是系统硬编码上限。首发目标是患者取得可编辑文字及可选图片，通过大众点评或美团的真实评价路径，在本人账号自主发布；有效落点、本人确认、外部真实发布分别记录，不伪造成功。用户规模增长后按扩展 PRD 逐模块恢复自助与自动化。

### 1.2 三种范围与本次选择

保留四个平台及完整后台，会继续承担视频合成、双库、交易和客服系统的工作；只做单平台可更快，但无法检验点评与美团各自的订单和评价资格差异。本次选择两平台写评价 + 公司人工交付 + 一个最小内部管理台，将高成本自动化和新增渠道后置。这是对旧四平台八任务商业 V1 范围的阶段性收缩，不是将其永久删除。

### 1.3 首发流程与角色

公司核验签约资料和实际到账 → 录入医院/医生及少量授权素材 → 人工一次审核 → 绑定、发货并协助验收贴片 → 开通有效服务期 → 患者碰触/扫码 → 选择点评或美团 → 自动生成 → 可选改文/添图 → 复制保存及对应引导 → 本人发布 → 返回自述确认。

患者匿名；医院通过约定负责人提供和核对最少资料，不需学习或登录 SaaS；公司使用按人独立的管理员账号处理试点机构。财务、审核和售后仍须有实际依据和责任人，使用受权限控制的现有工具/台账承接。公司人工不意味着前端可绕过租户、安全、审核、授权及到期检查。

### 1.4 当前范围与后置能力

| 范围 | MVP 交付 | 后续扩展 |
|---|---|---|
| 发布渠道 | 点评、美团写评价 | 两平台打卡/收藏、小红书图文、抖音视频 |
| 患者编辑 | 正文改写、换一篇、最多3张可选图片、逐图删除/重试 | 大图库、排序/替换、HEIC/视频、字幕片段编辑；不恢复已取消的跨页面患者历史 |
| 管理与开通 | 公司最小管理台、少量资料、人工核验与上线 | 医院自助 SaaS、成员角色、批量导入、完整上线中心及员工任务系统 |
| 素材 | 每院少量公司维护的授权文字与图片、一次审核 | 平台公共库、医院私有库自助、选用清单、完整审核队列与视频模板 |
| 商业交付 | 人工合同核款/开票/退款/物流、系统有效期限与额度 | 自助订单支付、套餐升降级折算、自动续费通知及完整售后 |
| 支持和数据 | 联系人、人工异常台账、必要监控/审计/完成记录 | 消息中心、工单 SLA 自动化、服务日历、医院数据看板与自助导出 |

原合同或法定必须履行的事项不能通过需求后置省略。若已有合同约定四平台、宽限期或响应时限，由负责人先安排实际履行或取得合法的范围调整，再让该机构参加本阶段试点；本 PRD 不单方改合同。

### 1.5 已确认原则保持有效

不根据差评情绪弹窗或分流；服务反馈常驻、患者自主联系医院。患者不先填写消费经历，只提示可改自动生成文字和可选上传图片。默认不加重复 AI 来源说明或教程，依法及平台明确要求的最短标识仍须执行。医院只提供最少信息，已有资料复用。患者文字、素材仅存续页面临时保留，关闭/刷新后不恢复；外部发布切换不是立即清除依据。

### 1.6 发布门槛和衡量

只开放已通过设备/平台/医院对象核验的组合；零填写事实文案若不符合某平台评价规则，不准通过宣传包装绕过。MVP-030 的小样本门槛仅用于试点上线验证，不能宣传为稳定达到旧商业版 99%/98%/95% 指标；扩大交付时须恢复扩展 PRD 的适用商业验收并重新制定充分样本方案。上线复核、人工核款/审核/安全处置是交付工作，不是等待后期再做的事项。

### 1.7 需求维护与扩展

各模块使用“需求内容、具体细节、验收标准”三列表，32 项均为当前 P0。新编号 MVP-001–MVP-032 只用于当前收缩范围；旧编号全部在扩展 PRD 保留，并附承接映射。本文对当前开发范围及收缩规则具有优先效力，扩展文档里的历史优先级、SLA、九张图片/视频/四平台承诺不自动生效。后续新增设计放入所属表，明确实际启用范围和依赖；不通过继续拆细条目无限扩张 MVP。

## 2. 各部分具体需求

<a id="mvp-part-1"></a>

### 2.1 患者入口、编辑与发布

| 需求内容 | 具体细节 | 验收标准 |
|---|---|---|
| <a id="req-mvp-001"></a>**MVP-001 · P0 贴片入口与加载** | NFC 与二维码进入同一唯一贴片入口，绑定唯一机构和医生；患者不登录、不选择医院或医生。显示正确医院、医生姓名，头像和 Logo 可用中性占位。读取时显示加载状态，10 秒未完成显示重试；未绑定、停用、医生离职或机构服务到期显示中性维护页和有效医院联系方式，不泄露欠费信息、不让患者自行纠错。 | 两个入口读到同一绑定；无效状态不进入生成；加载失败可重试、不串机构；不收集患者账号。 |
| <a id="req-mvp-002"></a>**MVP-002 · P0 两平台评价主流程** | 首发仅大众点评、美团写评价；不提供打卡、收藏、小红书或抖音入口。路径为选择平台 → 自动生成一篇 → 可选改文/添图 → 复制保存与指引 → 患者在本人账号发布。无生成前消费经历、项目或感受表单，不预选星级。只有实机验证通过的设备与任务组合可开放。 | 两条评价路径独立，不自动代发；无强制消费经历填写；无后置功能的虚假入口。 |
| <a id="req-mvp-003"></a>**MVP-003 · P0 正文编辑与换一篇** | 正文可直接编辑，提示仅为“以下文字可直接修改。”按当前平台已核验字数限制就近指出超限；超限阻止交付但保留输入。“换一篇”仅从本院已审基础事实重新生成，不把手工修改隐式送给模型改写；有修改时提醒替换影响，新文成功后供使用或保留旧文，失败不覆盖。没有历史版本列表或跨页面草稿。 | 手工内容不被静默改写；失败保留当前文；超限可修正；未主动同意的修改不用于模型改写或训练。 |
| <a id="req-mvp-004"></a>**MVP-004 · P0 基础图片添加与删除** | 点评/美团支持纯文字路径（以已验证平台规则为准），图片可选。最多 3 张待发布图片，含自动选用的本院图片、患者上传及处理中图片，平台更低限制从严；仅 JPG/PNG/WebP，单张 ≤10 MB、长边 ≤12,000 像素。选文件前展示最短用途、临时保留及必要权利确认，不默认勾选。逐图显示处理中/可用/失败；检查真实类型、损坏/恶意文件、敏感信息，纠正方向并清除 EXIF。超限指出文件和剩余名额，不静默截断。可删除及重试失败项；不做图库挑选、排序、替换保留双版本、HEIC 转码或患者视频。 | 不上传也可走已验证纯文字路径；数量含待处理项且并发不超限；单图失败不撤销成功项；取消不丢文字；未检查通过不能交付，患者图片不进入医院库。 |
| <a id="req-mvp-005"></a>**MVP-005 · P0 复制与图片取得** | 正文单独复制，API 明确成功才显示已复制，失败可手动选择。图片逐张保存；区分下载已发起、患者确认已保存和可验证已保存，不把下载请求当作写入相册。正文修改只使其复制状态失效，新图片只使对应保存状态未就绪，不清空无关准备项。有处理中或失败图时等待、重试或主动移除，不静默漏图跳转。 | 复制失败有备用；文件可实际取得；无虚假已保存标记；修改后的当前正文和图片准备状态正确。 |
| <a id="req-mvp-006"></a>**MVP-006 · P0 大众点评评价指引** | 准备页说明先复制文字、保存可选图片；按已验证策略打开本机构评价入口，不能直达时打开正确门店并展示简短步骤：核对门店 → 写评价 → 粘贴/选图 → 自主评分 → 核对后发布。评价资格以实际平台规则为准，不伪造消费凭证；未登录、未安装、无资格或深链失效时说明具体可行操作并保留存续页面内容。 | 正确门店、主/备用路径和手动步骤实机通过；无资格不改门店或伪造记录；平台按钮来自核验。 |
| <a id="req-mvp-007"></a>**MVP-007 · P0 美团评价指引** | 独立维护美团门店和步骤，不复用点评验证结论。实际路径需要订单时，指引患者在本人美团账号找到对应可评价订单，不读取订单、不承诺直达本人订单。按该平台版本说明核对机构/消费记录、粘贴正文、选图、自主评分及发布；无订单、过期、登录或跳转失败提供实际限制和备用步骤。 | 美团单独验证；不读取患者订单；无资格不伪造成功或自动跳去点评；医院目标正确。 |
| <a id="req-mvp-008"></a>**MVP-008 · P0 帮助、返回与完成确认** | 操作帮助按当前平台展示简短步骤，可随时重开，不新增长教程。从发布平台返回时，仅在原页面仍存续且内容未失效时继续；提供“我已发布评价”和“尚未发布，查看帮助”。完成只记录患者自述，不算平台验证，可撤销更正，同会话同任务幂等；返回本身不代表发布成功。 | 帮助不丢存续内容；重复确认不增次数；返回/页面隐藏不伪造发布或有效落点；失效说明并重新生成。 |

### 2.4 素材与内容生成

| 需求内容 | 具体细节 | 验收标准 |
|---|---|---|
