# 口腔医院 NFC 碰碰贴商业化产品设计

- 日期：2026-10-10
- 状态：已完成方案评审，待用户复核书面规格
- 目标版本：正式商业版 V1
- 首要客户：单体民营口腔医院或诊所
- 首要购买决策人：院长或老板

## 1. 文档目的

本文档把竞品分析结论转化为可产品化、可商业交付和可验收的完整方案。它同时定义长期产品全景、商业版 V1 范围及 PoC、试点 MVP 与商业版 V1 的内部验证顺序。

本设计不把“生成了 AI 内容”视为产品成功。成功意味着患者取得完整文案和素材，到达可执行的目标平台页面，并在核对真实性后主动发布。

## 2. 产品定位与价值

产品是面向口腔机构的 AI 口碑营销 SaaS。它使用医生专属 NFC 碰碰贴和二维码触达患者，以当前医生为内容主线，生成真实、合规且适配平台的内容，并帮助患者完成发布前的文案、素材和落点准备。

核心价值按优先级排序为：

1. 提升真实公开评价数量，首要平台为大众点评/美团。
2. 通过小红书图文和抖音短视频扩大医生及机构曝光。
3. 把医疗真实性、素材授权和平台规则纳入生成前约束。
4. 以可验证的发布闭环替代“功能入口存在即算成功”的展示型能力。

## 3. 用户与角色

### 3.1 患者

在就诊服务结束后，由医生或前台自然邀请使用。患者不需注册、登录或提供手机号，可直接生成基础内容。患者始终拥有预览、修改、删除、放弃和主动发布的决定权。

### 3.2 院长/机构管理员

负责机构资料、账号、套餐、医院终审、功能启停和经营数据。其首要关注点是真实评价增长、风险和投入产出。

### 3.3 机构运营人员

负责医生、项目和素材资料，发起审核，绑定贴片，处理告警并查看发布漏斗。V1 不提供医生账号、前台账号或自定义角色。

### 3.4 平台运营/合规人员

负责租户开通、平台初审、异常交付、落点策略、运行告警、套餐及宽限期管理。标准流程由系统自动执行，人员仅处理需要判断的审核与异常。

## 4. 范围与版本边界

### 4.1 商业版 V1 必做

- 同时支持大众点评/美团、小红书和抖音。
- 点评/美团包含写评价、打卡和收藏三个独立任务。
- 移动 H5 患者端，NFC 和二维码复用同一入口链接。
- 医生专属贴，贴片唯一 ID 在后台绑定具体机构和医生。
- 零填写、零患者素材可生成；项目、感受、照片和视频均为可选增强。
- 生成 1 份初稿，支持换一篇、直接修改文字及替换/删除素材。
- 文案复制、图片/视频保存、发布前检查、有效落点、失败恢复和患者确认完成。
- 机构 SaaS、平台运营后台、多租户隔离、双审核、套餐权益、贴片生命周期、漏斗数据和运行告警。
- 平台协助开通且尽量自动化：资料解析、字段预填、基础校验、AI 合规预检、批量绑定和上线检查。

### 4.2 V1 不做

- HIS、预约或排班系统对接，但数据模型和 API 保留扩展边界。
- 患者账号体系、原生患者 App 或以微信小程序为双主端。
- 连锁总部—门店组织、代理商、分润、自定义权限和复杂审批。
- 会员、私域、团购、Wi-Fi、红包、抽奖和专业视频编辑器。
- 自动登录患者平台账号、代发、好评筛选或虚构发布成功。

## 5. 产品架构

系统分为四个产品域：

1. **触达层**：NFC 贴片、二维码、唯一贴片 ID 和贴片生命周期。
2. **患者端**：医生专属 H5、内容生成与编辑、发布准备、平台跳转、失败恢复和完成确认。
3. **商业管理层**：机构 SaaS 和平台运营后台，承担租户、套餐、资料、审核、贴片、数据和运维。
4. **内容与集成底座**：可信知识库、素材授权、AI 编排、合规规则、平台适配策略、设备能力检测与可观测性。

边界原则：患者端不依赖机构后台实时在线；AI 只读取已通过双审的资料；平台变化由适配层隔离；套餐及租户权益由统一商业化域判定。

## 6. 患者端设计

### 6.1 入口前置条件

贴片在使用前已绑定唯一机构和唯一医生。患者不确认、不选择医院或医生。页首展示医院 Logo、名称、医生头像与姓名，仅用于识别当前上下文。

实体贴不永久印制医生姓名，以机构品牌、碰触/扫码指引、二维码和唯一短编号为主。NFC 与二维码指向同一贴片入口。医生离职、调岗或贴片回收后，贴片可在停用、审计和重新上线检查后换绑。

若贴片未绑定、已停用、医生不可用或数据不一致，系统不允许患者自行选择医生，而是展示中性维护页和机构联系方式，并自动通知机构管理员与平台运营。

### 6.2 共用主流程

1. 患者触碰 NFC 或扫描二维码。
2. 系统读取贴片 ID，直接进入医生专属页。
3. 患者选择大众点评/美团、小红书或抖音。
4. 系统直接生成 1 份基础内容；患者可在生成前或后增加项目、真实感受或素材。
5. 患者预览、编辑、换一篇或删除素材。
6. 系统按平台检查文案复制、素材保存和必要凭证是否就绪。
7. 系统选择当前设备上已验证的最佳落点，失败则降级。
8. 患者在本人平台账号内主动发布，返回 H5 后可点击“我已发布”。

### 6.3 点评/美团任务组

- **写评价**：生成可编辑的真实评价草稿；跳转前提醒消费凭证等平台前置条件，确认文案已复制、素材已保存。
- **打卡**：明确说明用途、所需准备和平台内操作位置；能直达时进入已验证页面，否则打开正确门店页并展示图文指引。
- **收藏**：明确展示要收藏的门店页；无法直达收藏操作时，打开正确门店页并指明手动步骤。

三个任务互不依赖，任何一项都不是另一项的强制前置。系统分别记录尝试、有效落点和患者确认完成，不把打卡或收藏冒充为已发布评价。

### 6.4 小红书与抖音

小红书生成图文发布包。标题和正文始终分开可见、可分步复制，图片先保存再打开平台，不依赖一次剪贴板写入交付全部文案。

抖音基础视频由医院已审的医生、环境、设备和通用服务素材，结合已审模板、字幕、配乐和简单转场自动合成。系统确认视频已保存后才打开抖音，配文单独复制。

### 6.5 负面感受

患者选择或填写负面感受时，系统仍允许生成、编辑并自主公开发布。院内反馈入口作为并行选项，不得阻断、延迟或代替公开发布。

## 7. 机构 SaaS 与交付

### 7.1 信息架构

- **今日首页**：上线健康度、今日触达、发布漏斗和评价增量。
- **上线中心**：展示从资料导入到完成上线的进度、阻塞项与异常。
- **医生与项目**：管理已审核的医生事实、专长、项目和状态。
- **素材与审核**：管理来源、授权范围、使用期限、初审及终审。
- **碰碰贴**：入库、绑定、启用、停用、丢失、换绑、报废和历史记录。
- **发布数据**：按平台、任务、医生、设备和时间展示漏斗与失败原因。
- **套餐与账户**：用量、医生贴额度、超额加购、续费、宽限期和账号。

### 7.2 自动化交付流程

1. 销售订单创建租户、机构和套餐。
2. 批量导入并解析机构、医生、项目及素材资料。
3. 自动检查完整性、素材授权、敏感表达和重复素材。
4. 平台完成初审，机构管理员完成真实性终审。
5. 运营人员通过批量扫码或录入贴片 ID 绑定医生。
6. 系统执行生成、套餐权益和三平台落点检查，通过后上线。

只有资料缺失、授权过期、审核拒绝、贴片重复绑定或落点测试失败进入平台人工异常队列。

## 8. AI 内容与合规治理

### 8.1 可信资料库

可生成资料包含机构、医生、诊疗项目、设备、环境、合规表达、禁用词和已授权素材。仅“平台初审通过 + 医院终审通过 + 授权未过期”的资料可进入自动生成。

素材状态为待核验、限定使用、已授权和停用/过期。限定使用素材必须标注可用医生、平台、内容类型和时间范围。停用后立即从新生成中排除，但保留历史引用审计。

### 8.2 生成规则

- 无患者输入时，AI 可介绍已审核的医生资历、专长、环境、设备和通用服务，不得声称患者亲历某项治疗、获得某疗效或感到无痛。
- 有患者输入时，AI 仅使用患者明确提供的项目、感受和素材，不从照片推断疾病、身份、治疗结果或其他敏感特征。
- 每次生成后检查虚构体验、疗效承诺、未授权肖像、敏感信息和医生串用。
- AI 检查失败或超时时，在限定次数内重试；仍失败则返回医院已预审的中性模板，不向患者暴露技术错误细节。

## 9. 隐私、安全与审计

- 患者不登录；每次使用建立匿名会话。
- 生成草稿、患者上传素材和临时合成物默认 7 天后自动删除，患者可随时立即删除。
- 去标识化事件可单独保留，只包含漏斗节点、平台任务、设备类型、错误码、策略版本和时间，不包含发布文案、患者平台账号或原始素材。
- 机构、医生、素材、贴片、审核和统计数据强制带租户边界，跨租户访问默认拒绝。
- 审核、权益、贴片绑定/换绑/停用、素材授权和管理操作保留操作人、时间、前后状态和原因。
- 正式上线前必须完成医疗广告、个人信息保护和三方平台规则的专项法务复核。

## 10. 平台适配与错误恢复

每个外部跳转都按以下决策链执行：识别操作系统、App 和权限状态 → 完成文案/素材/凭证准备 → 选择已验证落点 → 记录跳转尝试 → 判断是否到达可执行页 → 失败时降级 → 返回 H5 可恢复。

降级顺序根据平台和设备配置，候选方式包含备用深链、正确门店页、手动图文指引、浏览器页面和应用商店。跳转策略、提示文案和功能开关必须可热更新，且携带策略版本便于回溯。

任何失败均不清空已生成内容。权限被拒时说明用途并提供重试或手动操作；App 未安装、未登录或深链失效时，使用已验证的备用落点并标记原策略待复测。

## 11. 商业模式与权益

收费结构为“机构年费 + 套餐内首批硬件 + 补发/超额硬件费”。不按患者单次生成收费，避免机构为降低成本而限制患者使用。

- **基础套餐**：含 5 个可用医生贴。
- **升级套餐**：含 10 个可用医生贴。
- **超额加购**：超过 10 个后，每个加购包增加 5 个可用医生贴额度。

两个套餐均含三平台、机构后台、双审核、标准素材库、发布漏斗和协助开通。V1 不向机构展示按次生成或按存储量计费的用量门槛；平台仅对异常自动化请求、恶意滥用和超出正常机构使用模式的行为执行技术限流。具体金额属于商务定价文档，不影响本产品功能边界。

套餐到期或超额后使用软限制：暂停新增医生/贴片及新内容生成，已有贴片进入 14 天宽限期并持续提醒续费。宽限期结束后展示不泄露商务细节的中性服务状态页。

## 12. 数据与指标

### 12.1 北极星指标

**患者确认发布率 = 完成“我已发布”的匿名会话数 ÷ 成功进入医生专属页的匿名会话数。**

该指标是患者主动确认，不等同于三方平台已回传发布成功。机构定期录入平台评价总量或净增量，用于趋势校验，不对单条评价做确定性归因。

### 12.2 漏斗事件

最小事件链为：入口成功 → 医生绑定读取成功 → 平台/任务选择 → 生成成功 → 预览/编辑/换一篇 → 文案复制 → 素材保存 → 跳转尝试 → 有效落点 → 患者确认完成。

平台、任务、医生、设备类型、操作系统/App 版本、跳转策略版本、错误码和耗时是关键分析维度。数据展示必须明确区分系统可观测事件、患者主动确认和机构手工录入的平台结果。

## 13. 验收与测试

### 13.1 V1 验收红线

- NFC/二维码入口成功率 ≥ 99%。
- 机构和医生绑定读取正确率 = 100%。
- AI 首次生成成功率 ≥ 98%，失败可返回安全预审模板。
- 文案复制成功率 ≥ 99%，标题与正文不互相覆盖。
- 图片或视频保存成功率 ≥ 95%。
- 声明支持的设备/平台/任务组合中，有效落点率 ≥ 95%。
- 无患者素材的基础路径从触碰到打开目标平台不超过 5 个主要操作：选择平台/任务、触发生成、确认内容、完成发布准备、打开平台。中位时长 ≤ 60 秒。
- 任一跳转、权限或平台错误后，已生成内容不丢失且可重试。

### 13.2 测试矩阵

- iPhone、主流安卓、鸿蒙各至少 2 款代表机型。
- 点评/美团评价、打卡、收藏；小红书图文；抖音视频。
- App 已安装/未安装、已登录/未登录、剪贴板和相册权限允许/拒绝。
- NFC/二维码、无患者素材/有素材、负面感受、换一篇和手动编辑。
- 每次测试记录设备、系统/App 版本、策略版本、文案/素材交付结果、最终页面、恢复结果和错误码。

## 14. 分阶段路线

### 阶段 1：技术 PoC

内部证明 NFC/二维码、医生绑定、AI 生成、素材交付、五类平台任务落点和失败恢复可行。PoC 不是对外销售版本。

### 阶段 2：试点 MVP

在 1–3 家单体口腔机构内验证真实患者使用、双审、贴片运营、设备矩阵、患者确认发布率和评价增量趋势。允许有限度人工运营，但重复步骤必须记录并进入自动化清单。

### 阶段 3：商业版 V1

同时对外交付点评/美团、小红书和抖音，且多租户 SaaS、套餐、双审、自动交付、监控告警、宽限期和标准客户支持全部就绪。只有达到验收红线的设备/平台/任务组合才能对外声明支持。

## 15. 关键风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 三方平台修改深链或发布规则 | 已上线路径突然失效 | 适配策略热更新、策略版本化、告警、快速复测和手动降级 |
| 无第三方发布成功回传 | 无法精确归因评价 | 明确区分有效落点、患者确认和机构评价增量，不宣称单条精确归因 |
| AI 生成虚构经历或疗效 | 医疗合规与品牌风险 | 可信资料库、生成前约束、生成后检查、预审模板降级和审计 |
| 患者素材或肖像未授权 | 隐私、肖像或版权风险 | 授权状态和使用范围、默认短保留期、立即删除、过期自动停用 |
| 贴片绑定错误 | 内容串医生，严重损害信任 | 唯一 ID、绑定检查、变更审计、异常不让患者自行纠错、正确率 100% 红线 |
| 协助交付过度依赖人工 | 扩张慢、毛利低、容易出错 | 标准步骤自动化，人工只处理异常；试点期记录并产品化重复工作 |

## 16. 完成标准

本产品设计视为完成，当且仅当：

1. 患者、机构、平台运营和 AI/适配底座的边界清晰。
2. 点评/美团评价、打卡、收藏，小红书图文和抖音视频均有交付、落点和降级定义。
3. 商业版 V1 范围、非范围、套餐、权益、指标和验收红线可直接用于实施规划。
4. 医疗真实性、素材授权、患者隐私、负面评价和发布责任边界无歧义。
5. 每一个外部平台依赖都可监控、可降级、可恢复并可通过矩阵测试。
