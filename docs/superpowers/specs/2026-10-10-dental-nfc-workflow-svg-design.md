# 口腔医院 NFC 碰碰贴 Workflow SVG 设计规格

- 日期：2026-10-10
- 状态：版式已确认，待用户复核书面规格
- 输出格式：Figma 可直接导入的纯 SVG
- 源文档：`2026-10-10-dental-nfc-commercial-product-design.md`

## 1. 目标

用一张完整产品泳道图展示从机构签约、资料审核、贴片上线、患者使用、三平台发布，到数据复盘与续费的端到端 Workflow。图中必须同时表达责任人、先后关系、关键决策、错误恢复和数据回流。

## 2. 画布与结构

- 画布：`3200 × 1900` SVG `viewBox`，横向阅读。
- 顶部：标题、副标题、版本与三种连线图例。
- 主体：7 个等宽阶段列 × 6 条角色泳道。
- 右侧：指标、验收红线和不可跨越的责任边界。
- 底部：跨阶段错误恢复带与数据回流带。

## 3. 阶段列

1. 签约与开通
2. 资料与双审
3. 贴片绑定上线
4. 患者触达
5. AI 内容生成
6. 三平台发布
7. 数据复盘与续费

## 4. 角色泳道

1. 患者
2. 机构运营
3. 院长/机构管理员
4. 平台运营/合规
5. AI/合规/适配系统
6. 外部平台

每条泳道使用序号、文字标签和辅助色区分，不仅依赖颜色表意。

## 5. 主流程节点

- 销售订单触发创建租户、套餐和机构账号。
- 机构运营批量导入机构、医生、项目和素材。
- 系统自动预检，平台初审，机构管理员终审。
- 机构运营批量绑定贴片 ID 与医生，系统执行上线检查。
- 患者触碰 NFC 或扫码，直接进入已绑定的医生专属页，不确认或选择医生。
- 患者选择平台/任务，AI 使用已通过双审的资料生成 1 份可编辑内容。
- 患者复制文案、保存素材，系统完成发布前检查并选择有效落点。
- 外部平台包含点评/美团写评价、打卡、收藏，小红书图文及抖音视频。
- 患者主动发布并可返回确认完成。
- 系统生成发布漏斗，机构定期录入评价总量/净增量，院长查看结果并续费或加购。

## 6. 异常与数据回流

- 红色虚线：资料缺失、授权过期、审核拒绝、重复绑定、落点失效、权限拒绝或 App 不可用。
- 异常必须指向可执行的恢复节点：异常队列、补齐/重审、停用告警、备用落点、手动指引或预审中性模板。
- 蓝色点线：入口、生成、复制/保存、跳转、有效落点和患者确认数据返回机构与平台数据层。
- 任何跳转失败均不清空已生成内容。

## 7. 视觉系统

- 风格：医疗 SaaS、专业、高对比、低装饰。
- 主色：`#0F172A`；强调色：`#0369A1`；背景：`#F8FAFC`；卡片：`#FFFFFF`；错误：`#DC2626`。
- 文字：优先使用 `Inter, "Noto Sans SC", "Microsoft YaHei", sans-serif`，保留可编辑 SVG 文字。
- 正文与背景对比度按 WCAG AA 最低 4.5:1 设计，连线与背景至少 3:1。
- 节点使用 12 px 圆角、1.5–2 px 边框和轻量阴影；保持 8 px 节奏。
- 流程状态同时使用标签、连线样式和颜色表达，避免仅靠红/绿区分。

## 8. Figma 导入要求

- 使用纯 SVG 基础元素：`rect`、`path`、`line`、`circle`、`text`、`tspan`、`g`、`defs`、`marker`和 `filter`。
- 不使用 `foreignObject`、HTML、外部字体、外部图片、JavaScript 或 CSS 动画。
- 所有视觉元素使用有意义的 `id` 和分组，方便 Figma 导入后查找与编辑。
- 使用 SVG 1.1 兼容语法，文件编码为 UTF-8，包含 `title` 和 `desc`。

## 9. 验收标准

1. SVG 通过 XML 解析，不引用任何外部资源。
2. 在 Figma 导入后可正常显示中文、阶段列、泳道、节点、箭头、图例和指标卡。
3. 100% 缩放下标题和阶段可读；放大后节点文字不截断、不溢出。
4. 主流程、异常恢复和数据回流在图例和实际连线中保持一致。
5. 图中明确表达贴片已预绑定医院/医生，患者不做确认；点评/美团的评价、打卡和收藏互相独立。
