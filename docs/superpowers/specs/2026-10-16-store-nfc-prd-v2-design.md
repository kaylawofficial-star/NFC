## 1. 整体设计

### 1.1 产品定位与核心卖点

面向所有需要提升真实顾客评价和口碑的线下服务门店，帮助门店降低素材准备、店员引导和顾客写评价的成本。医疗机构是其中一个行业场景，不再是唯一客户类型。

**核心卖点：绑定即用，无门店前置准备。** 推销人员到店完成 NFC 卡片与门店绑定，门店经理现场确认绑定即开始体验，随后即可使用；不再要求门店上传素材、准备300条内容、提供视频、添加医生或服务人员、注册后台或另点开通。

“无前置条件”指没有额外门店准备步骤，仍须正确识别门店与目标平台。本店缺少图片或某平台没有可执行路径时，系统如实显示能力范围，不能以其他门店实拍冒充本店图片，也不能承诺客观上不存在的图片或视频能力。

商业推广路径：平台及推销侧整理参考素材 → 到店绑定 → 店员免费体验 → 向老板展示可验证的工具使用效果 → 门店充值。拜访前准备属于供应侧运营工作，不是门店必须完成的事项，也不得成为每家门店依赖人工整理后才能使用的隐藏门槛。

### 1.2 用户与业务对象

| 对象/角色 | 职责与边界 |
|---|---|
| 门店 | 内容池、平台门店入口、免费额度、余额与贡献统计的基本单位；同一品牌不同门店独立核算 |
| 顾客 | 无需账号或手机号；选草稿、核对修改、删换补图、复制保存，自行在本人平台账号发布 |
| 门店经理 | 现场确认首次绑定及开始体验，决定是否使用服务天使；服务天使默认开启 |
| 服务天使/服务人员 | 记录店员引导顾客使用工具的贡献，不代表已发布，不自动成为素材所有者 |
| 素材归属人 | 医生或其他服务人员，可选；素材可仅归属门店，不强制每店绑定医生 |
| 推销人员 | 到店识别门店、绑定卡片并演示，测试操作与正式顾客使用区分 |
| 平台运营 | 内容整理、来源管理、分类复核、规则与平台入口维护、异常处理 |
| 财务及内部管理员 | 充值核账、账本更正、物料管理和内部权限；服务天使公共入口不能取得这些权限 |

### 1.3 顾客主流程

扫码/NFC进入 → 核对当前门店 → 选择平台及三类评论草稿 → 核对改文、删图/换图/补拍 → 按需复制文字、保存图片 → 点击前往平台 → 顾客自行发布。

服务天使已开启且至少有一名可用人员时，主流程提供可跳过的引导人员选择；未添加人员或服务已关闭时，该环节完全不出现。主页保留公共服务天使入口，供自行添加、管理人员；不验证门店权限、不要求登录。这里的“可跳过”和选择位置为本稿建议默认值。

不新增独立发布准备页，不要求复制、保存或确认完成后才能打开平台。准备动作在内容页完成，跳转按钮仍可直接使用。顾客可放弃、发表不同意见或修改评分，不预选好评、不筛选负面体验、不自动代发。

### 1.4 已确认的关键规则

| 事项 | 本轮确认结论 |
|---|---|
| 版本方式 | 完整新版，分阶段交付；原版保留 |
| 原有任务 | 全部保留；本轮先跑通点评、美团评价核心链路 |
| 内容池 | 扼要无图、扼要少图、详尽多图，每店每类目标约300条，持续更新 |
| 图片数量 | 初始0／1—3／4—5张，顾客编辑后全部待发布图片最多5张 |
| 不重复范围 | 全店共享、各类池独立轮换；草稿成功展示即消耗本轮名额，未跳转也不返还 |
| 顾客改文补图 | 仅本次使用，不进入门店候选池或公共池 |
| 收费事件 | 顾客点击对应App跳转按钮并发起跳转；不以复制、下载、实际打开或发布成功为前提 |
| 每日去重 | 北京时间自然日，同店、同设备、同平台最多一次；同平台不同任务合并 |
| 单价与赠送 | 0.8元/次，每店赠66次，首次开通起72小时有效 |
| 充值赠送 | 每笔到账均适用，按首次开通后经过时间分档；前24小时28%，24—48小时20%，48—72小时15%，72小时—30天8% |
| 有效期 | 每笔充值本金、赠送金额自实际到账起一年有效 |
| 扣减顺序 | 最早到期优先；同到期时间赠送部分优先 |
| 开通起点 | 经理现场确认首次绑定，绑定成功即开通；不增加单独开通操作 |
| 服务天使 | 经理可选、默认开启；公共入口自助人员管理不验证门店权限；关闭或无人员时不进入主流程 |
| 贡献口径 | 按去重后的有效工具使用记贡献，免费次数同样计贡献；与素材归属独立 |
| 公开评论 | 本店和同类门店公开文字可作生成参考；同类图片仅作选图参考，不交付 |
| 本店评论图片 | 不以另行取得复用授权作为入池前置；来源可追溯，权利状态不伪记为已授权 |

### 1.5 产品模块与数据流

系统由触达绑定、参考素材与交付素材、草稿内容池、顾客编辑交付、平台适配、使用账本、服务天使、充值及物料管理组成。

门店绑定生成稳定门店ID及绑定版本 → 系统自动组织该店候选 → 分配草稿并记录展示 → 会话内编辑和素材交付 → 跳转服务按门店/设备/平台/日期去重 → 同一有效使用关联扣费与一次贡献 → 后续仅按真实证据记录平台结果。

内容分配、收费、贡献、平台发布分别是独立事件；不能用其中任意一个代替其他事件。

### 1.6 分阶段范围

| 阶段 | 必须交付 | 出口条件 |
|---|---|---|
| S0 首店质量与手机闭环 | 首店真实素材、三类小池、全店轮换、编辑留痕、复制保存、点评/美团正确入口；绑定即用的演示 | 真机保存和平台落点有证据，图片无串店，计算每次使用的素材/生成/存储/人工成本；不以每类300条作为首轮门槛 |
| S1 免费体验及收费交付 | 自动首次开通、66次/72小时、跳转去重、免费及金额账本、充值赠送和到期、服务天使与贡献基础记录 | 边界、并发与对账验收通过，才能按本PRD价格正式收费；S0测试不冒充计费系统已实现 |
| S2 内容与运营扩容 | 各类约300条及持续补充、贡献榜、NFC/二维码库存/出入库/绑定履历、运营效率提升 | 内容质量和实际单位成本可接受，库存、扣费和贡献均可核查 |
| S3 原有其他平台任务 | 点评打卡/收藏、美团收藏、小红书图文、抖音视频、朋友圈分享及其编辑保存能力 | 各任务独立真机验收后开放；必要服务反馈按原P2后续提供 |

这是用户选择的“全部保留、分阶段验收”，替代旧版“全部患者任务必须同时首发”。各子系统后续分域规划，不在本轮编写代码或自动生成开发任务。

## 2. 各模块具体需求

以下保留原版三列表格形式，使用新命名空间避免与历史编号冲突。阶段表示交付先后，不表示允许省略已启用能力所需的数据、安全和真实性约束。

### 2.1 绑定与立即可用

| 需求内容 | 具体细节 | 验收标准 |
|---|---|---|
| ENT-001 · S0 门店识别 | 推销人员在绑定操作中选定真实门店，核对名称、地址、平台门店标识/链接；复用平台可取得的信息，不强制门店重复填写。系统生成门店ID，不能仅按同名合并。 | 同名不同地址不串店，点评与美团门店分别核对；无法确认门店时不绑定错误对象。 |
| ENT-002 · S0 绑定即用 | NFC与二维码使用同一卡片入口，绑定门店，无强制医生归属。经理确认首次绑定后原子记录开通时间；额外卡片、换绑、重复提交不重置已开通门店时间、优惠或66次。绑定完成无需第二次激活。 | 空白新店无需上传、人员配置、视频或后台注册即可进入可用主服务；并发绑定只创建一次开通权益。 |
| ENT-003 · S0 自动内容准备 | 平台侧已有行业参考、生成规则及自动本店信息整理承接零准备体验；后台异步扩充，不把运营审核待办变成门店任务。绑定后可立即取得首份草稿，后续按池补齐。 | 不出现“请先准备300条/20张图/一段视频才能使用”；首份不可用如实显示并记录为绑定即用验收失败。 |
| ENT-004 · S0 状态与版本 | 未绑定、停用、遗失或错绑卡片显示中性维护状态；换绑先停旧绑定，核对并生成新版本，旧会话不得按新店继续取材、扣费或记贡献。关闭服务天使只影响相关流程。 | 换绑不串店；旧会话无法改变计费门店；服务天使关闭不关闭评价服务。 |

### 2.2 参考评论、图片与生成

| 需求内容 | 具体细节 | 验收标准 |
|---|---|---|
| SRC-001 · S0 来源分类 | 分开存储本店公开评论文字、本店公开评论图片、同类店公开文字、同类店参考图片、门店提供素材、顾客临时素材。登记来源平台/链接、原门店、采集时间、对象ID、原评论关联和处理版本；原始内容和整理结论区分。 | 能从每条草稿及库图追溯来源；同类店图片无法经“参考”状态进入顾客下载集合。 |
| SRC-002 · S0 文本整理 | 同类评论用于评价维度、行业词汇和表达结构，本店历史评论辅助了解本店。去重、去个人信息、不整段照搬；不能把其他顾客历史经历、价格、人员或效果当作当前顾客已发生事实。 | 无串店、照抄或凭空生成亲历/疗效；顾客能够直接核对修改；来源数量不等于真实原创候选数量。 |
| SRC-003 · S0 本店公开图片 | 按用户确认，本店已有公开评论图片不要求另行取得授权才入候选。记录为“本店公开评论来源，未另行核验复用权”，不能自动标为已授权。入可选集合仍需确认确属本店、内容质量、隐私及重复检查；投诉、误归属及删除有停用渠道。 | 本店图与参考图明确分离；未核验权利状态可查；原评论删除/投诉关联素材可暂停交付，不依赖顾客重新绑定。 |
| SRC-004 · S0 图片分类复核 | 图片标注场景、对象、近似组、清晰度、宣传类、可用/待确认/停用状态。自动识别不等于原图复核；宣传类保留但默认不推荐，待确认不进入默认选图。 | 近似画面和同场景组可用于组合筛选；可选数量、已识别数量和人工复核数量分别显示。 |
| SRC-005 · S0 图片组合 | 有图草稿从本店可选集合选1—5张；少图1—3，多图4—5。组合避开同场景与近似画面；不以重复图凑数，文图一致，不自动补回顾客删除项。 | 同一组合无重复、近似图或重复场景；不足4张合格不同画面时不伪称“详尽多图已就绪”。 |
| SRC-006 · S0 素材不足 | 无本店图不能使用同类店图填充。保留三类入口及真实可用状态，允许顾客自愿补拍；纯文字仍可立即使用。有图类型不足须明确提示，不将所有新店默认设计为仅无图、不提前放弃自动整理本店公开素材。 | 有本店公开可用图片的新店自动支持有图草稿，无需上传；真正缺图不伪造完整三类服务。 |
| SRC-007 · S0 生成质量 | 无消费经历输入前置表单；正文只使用可依据的信息，顾客核对后自行决定。不得预选星级、强制正面词或屏蔽真实负面改文。保留原版零输入不虚构亲历及必要AI标识规则。 | 无输入不会声称“我接受某治疗”“已达到某疗效”等个人事实；负面修改不触发引导拦截。 |
| SRC-008 · S0 失效传播 | 原素材停用时，候选引用、衍生截图和待下载包同步重查；历史最小来源记录可保留但不能继续交付失效原图。参考素材可更新，已生成草稿保留规则版本。 | 旧URL不能绕过停用；失效只影响关联内容，不停用整店无关功能。 |

公开素材使用规则记录用户的产品决定，不构成权利核验结论。具体平台获取方式、可获取字段和复用边界在上线前留实际核验结果；不编造已取得授权或可持续抓取的能力，也不增加门店授权操作作为本轮入池前置。

### 2.3 三类内容池与全店轮换

| 需求内容 | 具体细节 | 验收标准 |
|---|---|---|
| POOL-001 · S0/S2 池结构 | 每店三类独立池：扼要无图、扼要少图、详尽多图。分别有草稿ID、类型、平台适配版本、来源、初始图片、状态和质量结果；每类约300条是扩容目标。 | 首轮小池也能运行；不把1114张图片或40条原评论直接称为900条合格草稿。 |
| POOL-002 · S0 扼要与详尽 | 本稿建议默认：扼要正文30—100个字符，详尽120—300个字符，均受目标平台更低限制约束；详尽增加可核对的信息维度，不用重复句凑长度。 | 正文长度可配置、平台规则可追溯；同一句改标点不视为新草稿。 |
| POOL-003 · S0 分配与展示 | 轮换范围为门店＋池类型，全店共同消耗；平台变体共享草稿母ID，避免同稿在不同平台重复占独立名额。先唯一预留再返回，顾客端确认成功渲染后消耗本轮名额；刷新、离开或未跳转不返还已展示项。 | 同店并发不会给两名顾客展示同一轮同一母稿；新设备和不同平台不能绕过全店轮换。 |
| POOL-004 · S0 请求幂等 | 同一次取稿、展示回执及网络重试共用请求ID；已展示回执重复不再消耗。未成功返回/显示的预留项建议5分钟后释放；已返回但展示状态未知的预留项本轮保守跳过，单独统计未知，避免重复曝光。 | 请求失败不伪记“已展示”；断网丢回执不造成并发重复展示；重试可取得原请求结果。 |
| POOL-005 · S0 轮次更新 | 无剩余可用、可分配项时开启下一轮；停用项不阻塞结束。新合格稿作为未展示项加入当前轮，旧稿仅修正标点不重置名额；整池不足或全部失效时停止该类型并说明。 | 三类互不抢名额；轮次切换并发只发生一次；跨轮避免连续同稿为本稿建议优化，不承诺永久不重复。 |
| POOL-006 · S0 换一篇 | 原页展示新稿成功后新稿消耗名额；旧稿不返还。失败保留现有编辑内容。顾客临时改文不会成为新候选或用于补充300条目标。 | 连续换稿不会反复取到同轮旧稿；换稿失败不清空顾客修改，不触发收费。 |

### 2.4 编辑、复制保存与本次内容留痕

| 需求内容 | 具体细节 | 验收标准 |
|---|---|---|
